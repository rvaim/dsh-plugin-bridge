# 插件桥使用与运维

> 插件桥 / Plugin Bridge 的 npm 包名为 `@rvaim/dsh-plugin-bridge`，Cordis 插件 ID 为 `plugin-bridge`，数据目录为 `$DSH_HOME/dsh-plugin-bridge/`。

> 当前支持独立 [Agent Plugins 1.0.0](<Agent Plugins 1.0.0 兼容说明.md>)，传统规则对照 Codex 0.163.0 和 CC 2.1.304。从 `0.6.0` 起仅支持包清单 `engines.dsh` 声明的 DSH 版本，管理入口位于侧边栏。当前 Plugin parser 为 `5.0.0`、Source parser 为 `5.1.0`；Claude Code / Codex 实现为 `1.2.0`，Agent Plugins 实现保持 `1.2.0`。2026-10-22 市场专项的官方资料与验证限制见[市场发现与选择安装验证报告](市场发现与选择安装验证报告.md)，开发契约见[解析器解耦重构说明](解析器解耦重构说明.md)。

## 1. 安装 bundle

安装 npm 版本 `0.9.0`：

```bash
dsh plugin --profile <profile-name> add @rvaim/dsh-plugin-bridge@0.9.0
```

离线或源码构建可在 `npm run verify` 后执行 `npm pack --ignore-scripts`，再安装生成的本地归档。

公开包地址：[npm：@rvaim/dsh-plugin-bridge](https://www.npmjs.com/package/@rvaim/dsh-plugin-bridge)。把 `<profile-name>` 换成实际 profile；首次安装或升级后重启该 profile 并刷新 Web 页面。

按原方式启动 profile。`plugin-bridge` 插件会提供 `ctx.pluginBridge` 服务，并在 `autoStart=true` 时恢复已启用 Plugin。

### 1.1 Web 管理面板

在 Web profile 中打开“侧边栏 → 插件桥”即可在线管理当前 profile：

- 开关会立即启动或停止整个旧 Plugin 的父 Cordis 实例；
- 卸载会先停止运行实例，再删除安装记录，并按 Source 引用规则回收内容；
- “添加”支持 Git URL、`github:` 简写、本地目录和归档；拉取期间显示进度；
- 独立单插件 Source 直接安装；Marketplace 无论一个还是多个候选都显示可勾选列表。确认后复用市场仓库的固定快照，只为选中的外部 Git 插件获取内容并记录 commit；未选中的外部来源不联网；
- 插件行中的错误或警告数量可以展开；错误会阻止启用，警告表示插件仍可运行但部分兼容行为可能不同。详情包含诊断说明、稳定代码、能力类型和关联文件；
- 点击刷新会重新读取插件状态并检查各 Source 的最新 revision；检测到更新时插件行显示“更新”按钮，确认后在线更新整个 Source 并重启受影响插件。

这些操作都通过当前 DSH 进程执行，不要求重启。只有首次安装、升级或删除 `@rvaim/dsh-plugin-bridge` 这个 DSH bundle 本身时，Host/Client 插件图发生变化，需要重启 profile 并刷新 Web 页面。

本包不提供独立 CLI。Web 页面负责常用的添加、启停和卸载；Source 维护、批量操作和自动化应使用下方的 `ctx.pluginBridge` 服务 API。

当前 DSH 的公开持久化接口不提供可读取的 transcript 文件路径。Hook payload 的 `transcript_path` 按既有协议配置输出空字符串或 `null`，不猜测存储目录；依赖该路径读取文件的第三方 Hook 需要单独验证。

### 1.2 动态分类与本地文件（0.7.0）

页面内部分类来自当前 profile 实际装配的解析器。新解析器自带分类声明，未安装该类插件时也显示 0；移除解析器后分类消失，已安装记录仍可从“全部”查看和卸载。分类数量基于完整库存，搜索及状态筛选进一步限定结果，不改变分类计数。

添加弹窗可输入来源，也可点击“选择本地文件”打开浏览器所在系统的标准选择器。支持 `.zip`、`.tar`、`.tgz`、`.tar.gz`，上限 30 MiB。选择文件不立即安装；点击添加后，归档字节经当前 DSH 的认证接口上传并解析。独立单插件继续自动安装；识别为市场时即使只有一个候选也等待选择。上传期间可以取消；安装事务开始后等待完成，避免中断原子操作。

文件选择与上传不依赖 Windows/macOS/Linux 专用命令。远程访问 DSH 时，选的是浏览器电脑上的文件，服务端收到实际内容，不把文件名当作 Host 路径；要安装 Host 上的目录，请继续在输入框中填写其路径。浏览器上传为固定内容快照，原电脑文件之后改变不会自动同步。

上传同时最多 2 个接收请求，单请求接收/准备期限 10 分钟；超时、断连及关闭释放临时内容，已返回的准备会话由原有完成/取消/TTL 管理。上传原件保存于 Source 的 `uploaded-origin.<ext>`，来源更新保留原件，来源回收一起删除。同摘要内容复用 Source，普通外部归档在上传接管后不再依赖旧路径。

架构和新增/移除解析器步骤见[动态贡献与本地文件选择](动态贡献与本地文件选择.md)。本节功能从 `0.7.0` 起提供。

## 2. Source 生命周期

### 2.1 添加显式 Source

```ts
await ctx.pluginBridge.sourceAdd('https://github.com/example/plugins.git', { as: 'example' })
await ctx.pluginBridge.sourceAdd('./plugins.zip', { as: 'local-market' })
await ctx.pluginBridge.sourceAdd('./monorepo', { as: 'monorepo', paths: ['packages/a', 'packages/b'] })
```

`sourceAdd` 只取得并扫描 Source，不会自动安装其全部 Plugin。

Web 页面“添加”成功时为新建来源创建隐式 Source；最后一个引用该隐式 Source 的 Plugin 卸载后，Source 自动回收。

### 2.2 查看 Source

```ts
const sources = await ctx.pluginBridge.sourceList()
const detail = await ctx.pluginBridge.sourceInspect('example')
```

`inspect` 显示：

- origin 与 ownership；
- revision/commit/SHA-256；
- 检测到的格式；
- 可安装 Plugin；
- 已安装引用；
- Source 与候选诊断。

### 2.3 更新 Source

```ts
await ctx.pluginBridge.sourceUpdate('example')
```

可替换来源：

```ts
await ctx.pluginBridge.sourceUpdate('example', { source: './replacement.zip' })
```

更新会整体影响该 Source 的全部已安装 Plugin。Source 新增的候选只出现在可安装列表，不会自动安装。

### 2.4 删除 Source

```ts
await ctx.pluginBridge.sourceRemove('example')
```

只要仍有 Plugin 引用，删除就会拒绝。显式 Source 引用归零仍保留；隐式 Source 由最后一个 Plugin 卸载时自动回收。

## 3. 安装 Plugin

### 3.1 Web 添加

在“侧边栏 → 插件桥”的添加弹窗中输入来源：

- 独立单插件 Source 拉取并解析后直接安装；
- Marketplace 显示可勾选候选，只有一条也必须选择；确认后从市场仓库固定快照安装，所选外部插件在此时获取；
- 取消、页面卸载或请求超时会回收本次创建且未被引用的临时 Source。

### 3.2 单插件 Source

```ts
await ctx.pluginBridge.install('./legacy-plugin')
await ctx.pluginBridge.install('./legacy-plugin.zip')
await ctx.pluginBridge.install('./legacy-plugin.tgz')
await ctx.pluginBridge.install('github:owner/repo#v1.2.0')
```

这会创建隐式 Source，并安装唯一可识别 Plugin。

### 3.3 Marketplace Source

市场来源不会默认安装任何候选，即使只有一条也必须显式传入 `plugins`：

```ts
await ctx.pluginBridge.install('https://github.com/example/plugin-market.git', {
  plugins: ['plugin-a', 'plugin-c'],
})
```

Web 之外的分步前端先 `prepareInstall` 取得候选与固定市场快照。是否展示选择由返回的 `selectionRequired` 决定，不按候选数量、厂商名称或清单路径猜测；市场返回 `true`，独立单插件可直接完成。随后完成或释放这个准备会话：

```ts
const prepared = await ctx.pluginBridge.prepareInstall('./plugin-market')
// 展示 prepared.plugins，等待用户选择……
await ctx.pluginBridge.completeInstallPreparation(prepared.preparationId, ['plugin-a', 'plugin-c'])
// 用户取消时只释放本次准备会话：
await ctx.pluginBridge.releaseInstallPreparation(prepared.preparationId)
```

完成时会复核来源实例与 revision，变化后明确要求重新准备；失败可重试。市场中声明的外部 Git/git-subdir 仅在选中确认后获取；`ref` 或默认 HEAD 在此次获取时解析为 commit 并记录，`sha` 固定指定提交。市场准备成功不表示外部仓库已可访问或插件已能运行。释放幂等，仅最后一个会话结束后才核验并回收原来创建、仍为 implicit 且没有安装引用的来源。来源已显式登记或被其他插件引用时会保留。不要使用 `sourceRemove` 代替准备会话释放。

一次选择多个 Plugin 时，静态阶段任一项失败则整个安装不提交。

### 3.4 从已添加 Source 安装

```ts
await ctx.pluginBridge.install('plugin-a@example')
```

或：

```ts
await ctx.pluginBridge.install('example', { plugins: ['plugin-a', 'plugin-c'] })
```

### 3.5 `paths` 兜底

```ts
await ctx.pluginBridge.install('./monorepo', {
  paths: ['packages/plugin-a', 'packages/plugin-b'],
})
```

规则：

- 只在 Source 没有 Claude/Codex Marketplace 时使用；
- 每个路径必须位于 Source 内；
- 每个目录重新经过正常 Plugin parser；
- 不会无限递归寻找候选。

### 3.5.1 嵌套市场发现

根目录已有市场时先使用根市场；根目录有显式插件清单时作为独立插件处理，不深入其内部找市场。两者都没有时，Claude Code 与 Codex 解析器通过签名声明最多深入 4 层寻找各自市场标记，总检查目录上限为 4096。不跟随目录符号链接，遇到市场或显式插件边界后不继续往下。仅扫描标记来定位清单，不把任意 Skill 目录猜成可安装插件；这个有界发现是插件桥扩展，不是上游递归约定。

例如 `plugins/claude_code/.claude-plugin/marketplace.json` 的市场根是 `plugins/claude_code/`，其 `source:"./reme"` 指向 `plugins/claude_code/reme/`。候选本地路径相对市场根解析，保存时改为相对整个 Source 仓库根；内联配置保留完整市场文件路径。Codex 同理，从市场根解析 `./` 路径，不以 `.agents/plugins/` 为基准。Claude Code 的 `metadata.pluginRoot` 先在该市场根内组合。

多个市场可共同提供候选；同格式、同 ID 的跨市场声明会阻止安装，避免静默选取一份策略。缺失目录、损坏清单、路径逃逸或断裂符号链接会显示诊断。npm、远端 archive、command 来源保留既有未适配诊断，准备和安装不执行来源插件的代码、构建或安装脚本。

市场发现不证明第三方运行能力兼容。ReMe 的 Claude Code 专用 auto-memory 等能力仍需单独核对环境与运行契约。

### 3.6 管理 ID

```ts
await ctx.pluginBridge.install('./plugin', { as: 'local-name', sourceAs: 'local-source' })
```

`as` 只改变插件桥的 Plugin 管理 ID；`sourceAs` 只改变 Source ID。不会改写 MCP `serverName`、Skill 名称或原插件内容。

### 3.7 启用策略

```ts
await ctx.pluginBridge.install('./plugin', { enable: false })
```

未传 `enable` 时，优先尊重 Marketplace 的 `defaultEnabled`/安装策略；没有相关声明时默认启用。静态 `error` 始终阻止自动启用。

## 4. Plugin 生命周期

Web 管理面板可直接开关和卸载；服务 API 等价调用为：

```ts
const plugins = await ctx.pluginBridge.list()
const detail = await ctx.pluginBridge.inspect('plugin-a')
await ctx.pluginBridge.disable('plugin-a')
await ctx.pluginBridge.enable('plugin-a')
await ctx.pluginBridge.uninstall('plugin-a')
```

`inspect` 显示安装记录、Source、统一能力、诊断与运行快照。

### 4.1 更新

Web 管理面板刷新后会自动检查更新；检测到新 revision 时点击“更新”按钮即可。共享 Source 的更新会整体影响该 Source 下的全部插件。

服务 API 先检查再更新：

```ts
const updates = await ctx.pluginBridge.checkUpdates()
// updates: SourceUpdateCheck[]，updateAvailable=true 时再执行更新
```

独占隐式 Source：

```ts
await ctx.pluginBridge.update('plugin-a')
```

共享 Source：

```ts
await ctx.pluginBridge.update('plugin-a', { confirmShared: true })
```

未传 `confirmShared` 时更新会以 `SharedSourceUpdateError` 拒绝，并列出全部受影响 Plugin。替换来源：

```ts
await ctx.pluginBridge.update('plugin-a', { source: './new-source.zip', confirmShared: true })
```

注意：这仍然是 Source 更新，不是只替换共享 Source 中某一个子目录。

### 4.2 priority

安装时：

```ts
await ctx.pluginBridge.install('./plugin', { priority: 10 })
```

恢复顺序为 `priority` 升序，再按 `pluginId` 字典序。当前版本不提供独立修改 priority 的 Web 控件；可在受控停机后修改 `state.json` 或重新安装。

## 5. 在线服务 API

其他插件可声明：

```ts
export const inject = ['pluginBridge']
```

然后使用：

```ts
const source = await ctx.pluginBridge.sourceAdd('./plugins.zip', { as: 'local-market' })
const installed = await ctx.pluginBridge.install(source.source.id, {
  plugins: ['plugin-a', 'plugin-c'],
})

await ctx.pluginBridge.disable('plugin-a')
await ctx.pluginBridge.enable('plugin-a')
```

共享更新：

```ts
await ctx.pluginBridge.update('plugin-a', { confirmShared: true })
```

服务还提供：

```ts
sourceAdd / sourceRemove / sourceUpdate / sourceList / sourceInspect
install / update / enable / disable / uninstall / list / inspect / prepareInstall
```

## 6. 常见问题

### Source 是市场或包含多个 Plugin

市场即使只有一个候选也会展示可勾选列表；独立单插件来源保留直接安装。通过服务 API 对市场直接 `install` 时必须传入：

```ts
plugins: ['plugin-a', 'plugin-c']
```

错误会列出全部候选 ID，不会默认全装。

### 共享 Source 更新被拒绝

处理：先检查列出的受影响 Plugin，然后通过服务 API 传 `confirmShared: true`。

### Plugin 已安装但未启用

在 Web 管理面板展开诊断详情，或调用：

```ts
await ctx.pluginBridge.inspect('<plugin-id>')
```

查看 `error` 诊断、能力冲突、缺失运行环境或不支持语义。修复原因后再启用。

### Source 不能删除

仍有 Plugin 引用，或存在损坏的 `install.json` 导致无法安全判断。先修复/备份元数据或逐个卸载引用 Plugin，不要强制删除共享 Source。

### MCP 处于 degraded

检查：

- 环境变量/凭据是否存在；
- command、cwd 和可执行文件；
- HTTP URL/Header；
- `failOnStartupError`；
- DSH MCP client 日志与 Sandbox 权限。

### Node 依赖 warning

插件桥不会自动运行包管理器。确认插件是否已经提交依赖或可直接运行；否则在受控环境中显式准备依赖，并评估第三方脚本风险。

### Windows 上 Bash 命令失败

不会自动转换为 PowerShell。安装 Bash/WSL 等插件明确依赖的环境，或者选择跨平台版本的插件。

## 7. 运维建议

- 日常操作优先使用 Web 管理面板；批量与自动化使用 `ctx.pluginBridge` 服务 API。
- 更新前查看 Source 的已安装引用。
- 对不可信 Source 先 `sourceAdd` / `sourceInspect`，再选择 Plugin。
- 定期备份 `installed/*/data` 和 Source 元数据。
- 不手工复制 Skill/MCP/Hook 到 DSH 全局目录。
- 不在运行中直接修改 `sources/*/package`。
