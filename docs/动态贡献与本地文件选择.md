# 动态分类贡献与跨平台本地文件选择

## 目标与范围

本轮在 `0.6.0` 发布基线上实施。DSH 全局仍只有一个“插件桥”入口；进入后按解析器贡献生成页内分类。新增文件选择使用浏览器标准能力，Windows、macOS、Linux 共用同一实现。协议 Manifest、Skill、MCP、Hook 的解析规则与已有安装安全策略保持。

## 统一贡献架构

共同约定为：提供方声明 → 所属实例装配登记 → 对应适配器接入 → 所属实例销毁时撤销。这里统一的是扩展和生命周期模型，不把 UI 元数据、技能 Provider 函数与网络连接混入同一张全局 Map。

- **解析器**在自己的导出声明中提供分类名称、本地化与排序。分类 ID 由解析器稳定 ID 决定；当前解析契约已强制 `format === parser.id`。
- **注册表/引擎**仅登记实际装配的模块贡献；注册返回幂等撤销函数，由引擎所有者统一释放。保留的识别 signatures 仍用于阻止格式误接管，不生成菜单。
- **Host 目录接口**返回当前有效分类；列表 RPC 一次返回 `plugins` 与 `categories`，不额外维护厂商名单。
- **菜单适配器**通用渲染分类，并使用相同目录解析插件行和候选中的格式标签，不保留固定平台名称表。
- **Skill/MCP/Hook**继续由外部插件的 Cordis 父实例拥有注册资源。其目标服务与分类目录不同，但遵循相同注册/撤销约定。

类别目录是可序列化数据：`{ id, label: { en, zh? }, order }`。源解析器声明可提供默认名称，装配时归一化；语言或排序的变化不应导致协议扫描缓存失效。解析器模块不导入 React、DSH 插槽或任何客户端运行实现。

### 所有权

| 贡献 | 提供方 | 生命周期所有者 | 消费者 |
| --- | --- | --- | --- |
| 协议分类 | 解析器模块声明 | 当前引擎/插件 Service 实例 | 页内分类导航、格式标签 |
| Skill Provider | 外部插件的统一 Skill 模型 | 外部插件 Cordis 父实例 | DSH SkillRegistry |
| MCP Client/工具 | 外部插件的统一 MCP 模型 | 外部插件父实例及 MCP 子 Fiber | DSH MCP/工具服务 |
| Hook 监听 | 外部插件的统一 Hook 模型 | 外部插件父实例 | DSH 事件总线 |

停用一个 Codex 插件只撤销其运行能力，Codex 分类仍由解析器贡献保留；解析器配置变化生效后，分类目录随新引擎变化。移除解析器不删除已安装记录或用户数据。

## 页面行为

- “全部”是固定页面能力，使用空选择标识，不与任何 parser ID 冲突。
- 已注册、零安装的分类仍显示数量 0；分类计数基于完整安装记录，不受搜索或状态筛选影响。
- 混合格式插件可出现在多个分类，“全部”按插件 ID 去重。
- 分类、搜索、状态筛选取交集。当前分类被移除后回到“全部”并提示；Host 读取失败保留已知目录和数据。
- 安装后清空检索/状态筛选，必要时回“全部”，使新增结果可见。
- 宽屏页内左栏；窄屏使用同一目录的原生分类选择控件。沿用 DSH 控件、主题和键盘语义。

## 跨平台文件选择与 Host 交付

浏览器标准 `<input type="file">` 打开当前系统文件选择器，接受 ZIP、TAR、TGZ、TAR.GZ 归档。目录和 Host 本地路径仍可手动输入。选择取消不改变原输入；不使用 PowerShell、AppleScript 或 Linux 桌面命令。

浏览器的 `File.name` 不是 Host 路径，不能把 fakepath 或客户端绝对路径直接提交给安装器。远程浏览器与 Host 也可能处于不同系统。因此选择的归档必须上传内容，再交给现有准备/安装会话。

已核对：DSH 的 `dsh-client-file-upload` 是 Agent/Session 附件服务，不能为了插件安装借用用户会话或创建 Agent。采用宿主连接层的认证与 owner-only streaming route 注册原语，插件自行拥有有界临时上传，而不另开服务器。

上传实现要求：

- 标准 File/Blob 请求体，流式读取并写入随机命名的临时目录，不一次性把整个文件转成 Base64。
- 30 MiB 压缩文件预算、有限并发、超时与断连取消；扩展名和声明长度只作前置约束，实际逐块字节数也必须限制。
- 使用 DSH 连接层已有认证、Host/Origin fence 和 owner 权限检查；不新增公共无认证上传端点。
- 文件名只用于安全扩展名与展示，不接受或回传任意 Host 写入路径。
- 上传完成后准备固定 Source；多插件返回现有选择请求，单插件走原安装事务。
- 临时归档与来源准备会话的所有权明确衔接；完成、取消、错误、超时和插件卸载均释放资源。已有归档路径穿越、解压预算、符号链接、CRC 等检查继续生效。

## 验收

1. 三个内置解析器、任意子集、零解析器、新增未知第四解析器：分类由贡献变化，客户端无平台分支。
2. 重复 ID、单 owner 撤销、幂等销毁、不同引擎隔离、Service 生命周期释放和标签本地化。
3. 分类数量/混合格式/空分类/当前分类消失/旧数据与异常记录保留。
4. 标准文件选择事件、选择取消、ZIP/TAR/TGZ、大小边界、分块字节限制、并发、超时、断连和清理。
5. 上传后的单插件安装、多插件选择/取消/失败恢复，不创建会话，不假设客户端与 Host 共享文件系统。
6. TypeScript/Typert、真实 SDK、八种解析器组合与打包检查；真实浏览器下桌面/窄屏、暗浅色、键盘和文件输入验收。

## 实际接口与扩展步骤

分类声明属于解析器自身：

```ts
export const exampleParser: PluginParser = {
  id: 'example-format',
  version: '1.0.0',
  category: {
    label: { default: 'Example', en: 'Example', zh: '示例格式' },
    order: 40,
  },
  signature: { id: 'example-format', manifestPaths: ['example.json'], marketplacePaths: [] },
  // detect / discoverSource / parsePlugin 实现该协议契约
}
```

[ParserCategoryRegistry](../src/parser/registry.ts) 的公共约定为 `register(owner, category): () => void` 与 `list(owner?): CompatCategory[]`。重复 ID 拒绝注册；存入和读出均复制数据；撤销函数幂等，只删除精确登记实例，旧 disposer 不会误删新 owner 同 ID 的条目。部分装配失败会回滚已登记的本实例贡献。

[ParserEngine](../src/parser/engine.ts) 继承并持有分类登记，提供 `categories` 和 `dispose()`；默认 registry 属于该引擎，可显式注入共享 registry，各引擎只公开自身 owner 的贡献。[CompatService](../src/service.ts) 在停止的 `finally` 中撤销解析器目录；即使运行实例停止失败，分类也不会作为悬挂贡献遗留。label/order 不进入 parser fingerprint，不引发协议缓存重扫。

Manager/Service 的 `listCategories()` 返回当前目录拷贝。[Gateway](../src/web/host/gateway.ts) 的 `list` ready 返回 `{ kind: 'ready', plugins, categories }`；8 个既有 RPC 名称不变，严格 codec 由生成链更新。客户端 `ParserCategories` 只消费目录，`formatLabel` 在同一目录查找并通过 DSH `locale.resolveText` 解析名称；未注册格式回退原 ID。语言变化不发额外目录/列表请求。

**新增解析器：** 在独立模块实现统一解析接口并声明 category，将其加入 composition 装配与格式边界声明，按原协议要求增加 fixture/解析测试。前端、管理层和其他解析器均无需增加平台分支。新解析器若产出现有统一 Skill/MCP/Hook 模型，沿用现有运行适配器；新增能力种类仍需要独立适配器，Command/Agent 当前继续只识别、不注册运行。

**移除解析器：** 调整 composition 或当前 `parsers` 选择，物理移除时同时取消装配 import；构建/重载后仅实际模块贡献分类。识别 signature 可保留用于缺失解析器诊断，不能用作菜单。此实现不承诺运行时热加载任意新源码。

上传入口由官方 `connection.fetch.register` 注册 `POST /api/plugin-bridge/upload`，`requestBody: 'streaming'`。Connection 在 handler 之前执行认证、Host/Origin 与 owner 权限检查。浏览器 `uploadLocalArchive` 使用相对部署前缀的同源 fetch，body 直接传 File，并用生成的 `beginAdd` result schema 校验响应；不是新增无认证服务或 Base64 RPC。

[ArchiveUploads](../src/web/host/archive-uploads.ts) 所有接收文件只落在经过校验的随机临时目录，未返回任何临时 Host 路径。归档完成后调用 `prepareArchiveInstall`，返回 selection；单个可安装候选由客户端继续调用原 `completeAdd`，多个候选等待用户选择。取消发生在接收/准备阶段时先释放来源；安装阶段继续原子事务，按钮阻止重复提交。

[uploaded-archive](../src/manager/uploaded-archive.ts) 在 Source 创建/接管时保留 `uploaded-origin.<suffix>`。新单插件来源使用摘要派生 `upload-<sha24>`，避免所有临时文件都叫 archive 导致冲突；同 SHA 复用已有 Source。命中普通外部归档时，在仓库锁及 Source 锁内复制原件并原子更新 origin，同内容已有准备组同步 origin，保留快照身份及原清理责任。来源更新将受管理原件复制到新 staging，回滚/删除仍复用原事务。普通手输归档路径不自动变成受管理上传。
