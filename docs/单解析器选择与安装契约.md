# 单解析器选择与安装契约

> `0.10.0` 采用本文的单解析器选择与安装契约。Plugin / Source parser 版本均为 `6.0.0`，Claude Code / Codex 实现均为 `1.3.0`，Agent Plugins 实现保持 `1.2.0`。本轮统一自动化与 SDK 验证记录见文末；历史报告仅代表其记录的阶段。

## 安装身份

每个安装实例固定一个 `parserId`。来源可以同时支持多个平台，管理候选也可以列出多个格式；安装时只选一个解析器，运行时只使用该解析器产出的 Skill、MCP、Hook、Command 与 Agent。

[InstallMetadata](<../src/types/plugin.ts>) 的 `parserId:string` 必填。`CompatPlugin` 继续保留 `formats:string[]`，选定后为 `[parserId]`；匹配未决时可列出全部格式，不新增 `CompatPlugin.parserId`。同一安装实例的更新与缓存重扫沿用安装记录中的选择。

旧的 `plugins:string[]`、缺少 `parserId` 的安装记录，以及缺少必填解析器快照的扫描记录不迁移、不兼容。升级前备份插件数据，再按新契约重新安装；不要从已有 `formats` 猜测选择，也不要编辑缓存冒充迁移。Source / Plugin 扫描缓存均要求 `parserSnapshot`，同时记录内容与解析器实现身份；缓存不能代替安装记录提供解析器身份。

## 匹配与解析

[CompatParserEngine](<../src/parser/contracts.ts>) 提供：

```ts
matchPlugin(root: string, options?: {
  marketplaceDefinitions?: MarketplacePluginDefinition[]
}): Promise<ParserMatch[]>
parsePlugin(root: string, options?: ParsePluginOptions): Promise<CompatPlugin>
// ParsePluginOptions 新增 parserId?: string。
```

[ParserMatch](<../src/types/parser.ts>) 的公开结构为：

```ts
interface ParserMatch {
  parserId: string
  label: { en: string; zh?: string }
  available: boolean
  evidence: Array<{ kind: 'manifest' | 'catalog' | 'implicit'; file?: string }>
  diagnostics: CompatDiagnostic[]
}
```

`matchPlugin` 只检测格式并预检核心清单，不完整扫描 Skill、MCP 或 Hook。标签来自解析器分类，缺失实现时使用 ID；依据来自实际清单、目录声明或隐式匹配。禁用选项也保留依据和诊断，供通用 UI 展示。UI 不按厂商名称、清单路径或目录形状推断选择。

| 条件 | 行为 |
|---|---|
| 唯一匹配且可用，未传 `parserId` | 自动选定并解析一次 |
| 多个匹配，未传 `parserId` | 只返回 `PARSER_SELECTION_REQUIRED` error 与空能力；不执行任何完整 parser |
| 已指定匹配且可用的 ID | 只执行该 parser；`formats` 为 `[parserId]` |
| 所需实现缺失 | `PARSER_UNAVAILABLE`，空能力 |
| 已注册 ID 不匹配插件 | `PARSER_MISMATCH`，空能力 |
| 所选目录策略或清单预检阻止使用 | 返回该选项的诊断，空能力 |
| 独占根清单存在 | 只匹配该格式；不能以指定其他 ID 绕过 |

“唯一匹配”按完整匹配集合判断；多个匹配中只有一个可用也需要明确选择。

## 目录实体与平台策略

同 ID、同真实位置的跨格式声明归一为一个管理实体；每个平台的目录定义分别保存 `installable` 和 `diagnostics`。候选级 `installable` 表示存在可选平台且没有全局结构冲突。摘要可能同时包含另一个平台的 error，不能据其 error 总数禁用全部平台。

[selectCandidateParser(candidate, parserId)](<../src/parser/model.ts>) 是中立投影 helper：过滤 definitions、平台 metadata、诊断与可安装性，保留候选结构冲突。调用方先通过 `matchPlugin` 验证实际匹配及可用性；helper 不重新检查目录结构。真实根清单支持但市场未声明的平台仍可选，其目录定义为空。安装编译阶段再次检查实际匹配。

同格式跨市场重复、同市场同 ID 重复、同 ID 指向不同位置等结构冲突继续阻断，不能通过选择或过滤定义绕过。平台间的 version、displayName、defaultEnabled 与安装限制各自解释；未选平台的限制不会污染选定平台。

不再执行跨格式 Skill/Command/Agent alias merge、MCP environment binding union 或 Hook 方言拼接。选定 parser 内部的重复检测、MCP 覆盖规则及目录与本地清单优先级仍由该协议拥有。Codex interface-only sidecar 只在选定 Codex 时提供 metadata；`allow_implicit_invocation:false` 等权限不与另一个 parser 的默认值合并。

## 服务 API

[InstallOptions](<../src/manager/types.ts>) 使用对象数组：

```ts
await ctx.pluginBridge.install(sourceOrSourceId, {
  plugins: [
    { pluginId: 'plugin-a', parserId: 'claude-code' },
    { pluginId: 'plugin-b', parserId: 'codex' },
  ],
})
```

`parserId` 可省略，但只允许唯一匹配。市场无论有几个候选都必须显式选择插件。非交互调用遇到多匹配时不会默认使用某一平台；需要交互时使用分步接口。

```ts
const prepared = await ctx.pluginBridge.prepareInstall(source)
// prepared.selectionRequired 控制是否展示插件列表；市场始终要求选择插件。
let completion = await ctx.pluginBridge.completeInstallPreparation(
  prepared.preparationId,
  [{ pluginId: 'plugin-a' }],
)

if (completion.kind === 'parser-selection') {
  // 调用方展示 completion.plugins 中每个候选的 matches，
  // 并提交相同 pluginId 集合及用户选定的 parserId。
  completion = await ctx.pluginBridge.completeInstallPreparation(
    prepared.preparationId,
    [{ pluginId: 'plugin-a', parserId: 'codex' }],
  )
}

if (completion.kind === 'installed') {
  console.log(completion.result.plugins)
}
// 取消、放弃或结束未完成会话时：
await ctx.pluginBridge.releaseInstallPreparation(prepared.preparationId)
```

完成接口返回联合类型：

```ts
type InstallCompletion =
  | { kind: 'parser-selection'; plugins: ParserChoiceRequest[] }
  | { kind: 'installed'; result: InstallResult }

interface ParserChoiceRequest {
  pluginId: string
  name: string
  matches: ParserMatch[]
}
```

`selectionRequired` 与 `parser-selection` 是两个阶段：前者决定选择哪些插件，后者决定每个安装实例使用哪个解析器。独立单插件只省略前者，仍可能进入后者。多个插件一次提交，全部解析及选择完成后才进入原子安装事务。

## 固定内容、重试与取消

准备会话先固定市场 Source 的身份与 revision。外部 Git/git-subdir 只在选定插件后获取，解析 `ref`/HEAD 并记录 commit；声明的 `sha` 固定目标。未选来源不联网。

返回 `parser-selection` 时保留已取得的插件内容；同会话重试选择复用这些内容，不重新 clone，也不跟随移动的 ref。固定后不能改选插件集合；需要修改时释放并重新准备。提交仍复核 Source 身份与 revision，发生变化则明确要求重新准备。

释放会清理外部暂存内容。只有最后一个准备会话结束且 Source 仍由本次隐式创建、无安装引用时才回收 Source；显式或仍被引用的 Source 保留。Web 取消、关闭及超时按现有会话生命周期释放内容，不用删除来源代替释放。

安装持久提交与临时目录回收分开：提交成功后的回收失败返回已安装结果并附 `TEMP_CLEANUP_FAILED` 警告，会话已消费，不能再次安装。该 Manager 的后续仓库操作重试回收。提交前准备失败且回收再次失败时，仍记录待清理目录并保留失败原因；取消或后续操作不会失去清理责任。两个同来源会话分别持有自己的暂存内容，取消一方不能删除另一方的固定内容。

## 更新、运行与诊断

更新继续使用必填的 `InstallMetadata.parserId`。新内容不再匹配时明确拒绝更新；实现被移除时报告缺失，不交给其他 parser，不从旧缓存恢复其能力。失败不提交新内容，已安装数据与既有事务回滚边界保留。

选择成功只固定解释规则，不保证来源中的第三方命令可在当前平台运行。`commandWindows` 等平台分支尚未适配；Bash 不会自动转为 PowerShell，依赖与凭据仍须满足所选插件要求。匹配、安装、启用和真实运行分别验证。

重新计算跨插件名称冲突时，仅清除并重算以下四个代码：`MCP_SERVER_NAME_CONFLICT`、`SKILL_NAME_CONFLICT`、`COMMAND_NAME_CONFLICT`、`AGENT_NAME_CONFLICT`。其他 parser 诊断，包括 `HOOK_TIMEOUT_CONFLICT`，继续保留；不按 `_CONFLICT` 后缀批量清理。

目录策略、清单预检及选择错误阻止进入安装；完整能力解析产生的 error 仍按安装/启用策略处理并阻止自动启用。界面显示的候选摘要不代替选定平台的诊断。既有功能范围见[传统插件兼容矩阵](<传统插件兼容矩阵.md>)，运维流程见[使用与运维](<使用与运维.md>)。

## 0.10.1 活动 RPC 契约检查

安装对象协议标识为 `single-parser-v1`。只读 `pluginBridgeAdmin.contract()` 返回 `{ protocol, acceptsSelections }`；它从当前 `typert.local` 读取 `completeAdd.plugins` codec，分别校验省略 `parserId`、指定字符串 `parserId` 的对象数组和旧字符串数组，并检查解析结果是无损 JSON。它不根据磁盘包版本或静态声明返回成功。

Client 在添加来源、上传归档、确认插件/解析器前重新检查该结果。缺少端点、协议不符或活动 codec 仍为旧字符串数组时，不调用安装业务并明确要求保存工作后完整退出重启 Harness。网络或权限失败保留原始错误，取消和列表操作不受阻断。当前正常契约继续严格拒绝旧 `string[]`、非字符串解析器 ID 和直接传递的嵌套 `undefined`，没有增加旧接口兼容。

本次现场只读探针确认运行中 Host 接受字符串数组、拒绝新对象数组，而磁盘 `0.10.0` 的 Host/Client 产物已一致；原因是 Loader 的包名 manifest 缓存不会在当前进程内过期。临时探针通过插件管理器卸载，没有执行插件安装业务。完整宿主重启是使已安装新契约生效的必要步骤。

回归覆盖真实构建 Client bundle、真实 SDK Gateway 和请求/响应 JSON 往返：插件选择 → 解析器选择 → 安装完成；另覆盖新 Client 接活动旧 Host、真正缺少 `contract` 方法的旧服务、非 JSON 解析结果和中途失配。`0.10.1` 全量 433/433 通过，真实 SDK 12 轮 RPC、8 种解析器移除组合及 581 个发布文件检查通过。当前进程必须重启后才会丢弃现场旧缓存，不能把内存回归等同于已重启后的浏览器现场验收。
