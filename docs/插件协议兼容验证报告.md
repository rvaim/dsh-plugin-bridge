## 实现摘要

- 分平台落实 Manifest/Marketplace 的默认发现、路径、优先级、CC strict 与 Hook 事件覆盖、同平台 MCP 顺序覆盖；Source 内联引用显式标记根目录种类，安装、更新和重启后仍能正确读取。
- 区分合法事件、未知事件、合法但运行未适配 Handler；函数模块与关键未知行为不静默丢弃。
- 支持 Codex wildcard/精确 matcher，保留工具 JSON；CC `onFailure:block`、通用停止语义和当前 DSH Shell/Agent 初始化接入新增回归。
- Hook `args` 走 subprocess argv，缺服务不降级为 Shell；失败日志与动态健康状态不再固定报告 pass/running。
- Codex Skill sidecar 隐式调用策略、CC 调用提示/布尔值、传统 MCP Header/env/bearer 与延迟 fallback 均有针对性验证。
- 未兑现的认证、权限、工具限制、Skill 执行语义等明确阻止启用；Command/Agent 继续只解析不执行。
- 项目文档中文命名，发布检查验证文档存在；旧验证事实保留在[历史版本验证报告](历史版本验证报告.md)。

## 当前 DSH 与实测边界

本轮没有安装、启停或改写当前用户 profile，没有实际执行第三方插件。Hook 测试使用受控 Shell/subprocess/Session/Agent 接口与真实共享协议的输出解析；Parser 测试只读临时配置，不执行配置中的命令。远端 MCP 握手、真实模型会话和浏览器点击未完成端到端验证。

项目开发依赖与 Typert 生成器仍为 rc.6。本轮没有扩大到整个 DSH Client/Typert 版本迁移：此前已确认当前 Desktop 要求的严格 codec `create()` 与 rc.6 产物 `schema` 格式不同。因此本轮构建、发布探针或解析测试通过均不能证明当前 Desktop Web 可挂载，仍须单独完成该运行时升级。共享 Hook Protocol 库仅复用 wire codec、结果合并与日志，不把其 rc.6 版本当作 Codex/CC 规范号。

Codex Rust regex 与 JavaScript regex 引擎不完全相同：本轮支持可由 JavaScript 编译的常见语法，未声明完整 Rust 引擎等价。DSH 不能复现的事件、Handler、PowerShell shell form、输入/输出重写、动态 Skill 命令、认证与策略能力明确保留诊断。只读取到字段或成功创建父 Fiber，不算这些能力已运行。
