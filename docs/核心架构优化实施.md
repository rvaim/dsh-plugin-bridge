# 核心架构优化实施与验收

基础成果已提交为 `737bb3c`（当前 DSH 迁移、侧边栏管理面板及 UI 优化）。本轮承接[架构审查](架构与界面优化审查.md)，只实施已确认的职责与故障隔离改进。

## 固定边界

- 解析器、三个协议实现、装配、统一解析模型、解析测试及 fixture 不改；解析行为和版本不变。
- 保留现有仓库 → Source → Plugin 锁顺序、来源/外部目录原子切换、停止失败不删内容、失败恢复材料保留等语义。
- 不使用旧 DSH 兼容分支、不引入全局事件总线或通用事务/租约框架。
- 不推送、不发布、不安装到用户 profile；受控测试不执行用户 Hook/MCP。

## 本轮实现

1. **准备安装资源由管理层拥有（P1）。** `prepareInstall` 返回专用 `preparationId`；管理器保存固定 Source 身份、revision 和准备会话。`completeInstallPreparation(id, plugins)` 在仓库锁内校验后安装、成功后结束；`releaseInstallPreparation(id)` 在同锁内撤销，最后一个会话结束时仅回收仍为原实例、仍为 implicit 且无引用的来源。显式 `sourceRemove` 保留用户主动删除语义。不同浏览器请求不再各自维护来源删除权限。
2. **慢探测不占用仓库锁（P1）。** `checkUpdates` 在短锁中捕获来源身份、origin、revision 和受影响插件；锁外执行来源探测；返回前重验快照，变化或已删除的来源产生明确过期检查结果，不给新实例错误附加旧结果。定向测试使用可控 Promise，不依赖真实网络延时。
3. **运行协调显式化（P2）。** repository 只读/刷新记录；manager 的明确协调方法继续在查询、inspect、更新及启动路径撤下过期能力。存储不可读与运行协调失败分别表达，保留已有 fail-closed 测试。
4. **内容准备与事务职责解耦（P2）。** 安装与更新复用 manager 内的命名内容准备/静态检查函数，取消更新模块对 manager 私有方法的绑定。事务整体保留锁、暂存、切换和补偿边界，不为缩短文件拆散回滚。
5. **SDK 接入类型收紧（P2）。** Host 入口与 Service 使用真实 Cordis Context；运行层采用窄官方契约，MCP 配置使用官方联合类型，动态加载出口为明确插件类型；测试替身满足同一边界。
6. **Host 请求终态收敛。** RPC 门面保留 DTO 映射；独立小模块管理准备请求计时、完成/取消互斥和关闭清理，不再缓存 `sourceCreated` 作为删除授权。

## SDK 集成边界

将测试生命周期替换为真实 Cordis 后，现有回归验证了两项必须在接入层处理的细节：官方配置 schema 对特殊字符串字典键的保留，以及第三方插件启动错误在 Cordis 自身记录前的脱敏。修复应保留官方 schema 的标量验证/默认值，在每个 MCP 挂载边界保留已构造的安全字符串字典，并在错误跨入 Cordis 生命周期前脱敏。不得修改解析规则或降低现有 Header/Token 安全断言，也不应以只观察某个日志等级来掩盖错误。

## 验收

- 准备 → 显式登记同源 → 取消/过期：来源保留。
- 准备 → 其他入口安装引用 → 取消：安装和来源保留，请求正常结束。
- 多准备会话、不同网关、重复完成、完成/取消/过期竞争：不重复安装，不误回收。
- 源实例替换或 revision 变化：旧准备会话不能安装/清理新实例。
- 阻塞远端探测时 `list`/不相关 `disable` 可完成；来源检查过程中变更时结果标明已失效。
- 查询仍撤销过期运行能力；运行协调失败不误报安装记录损坏。
- 安装更新回滚、外部来源、凭据脱敏、生命周期清理回归全部保持。
- TypeScript、Typert、真实 SDK 探针、全量测试、八种解析器组合和包结构检查；最后提交优化结果。

## 实施结果

全部六项已实施：

- [manager.ts](../src/manager/manager.ts) 持有准备会话，完成/释放在同一仓库事务复核目录实例、创建身份、origin、revision、所有权和引用；探测在锁外执行并回锁检查快照。
- [repository.ts](../src/manager/repository.ts) 不再保存运行回调；manager 显式协调仍保留过期能力撤销，列表以 `PLUGIN_RUNTIME_SYNC_FAILED` 区分运行错误和记录不可读。
- [plugin-preparation.ts](../src/manager/plugin-preparation.ts) 统一安装与来源更新的内容准备/静态检查；三个提取函数与完整来源更新事务经标准化语法树比较，仅依赖访问和约定调用变化，锁、切换与补偿顺序保持。
- [install-requests.ts](../src/web/host/install-requests.ts) 收敛 Host 计时、重复完成、取消竞争与关闭清理；8 个 Web RPC 签名/DTO 不变。
- [运行时契约](../src/runtime/context.ts)、[MCP 挂载](../src/runtime/adapters/mcp.ts) 与 [Service](../src/service.ts) 使用真实 SDK 类型；删除旧 MCP ambient 声明。

最终 `npm run verify` 通过：**270/270 项测试**（比基础成果新增 32 项）、TypeScript/Typert/Client 构建、真实 SDK 严格注册和 4 次 RPC 往返、8 种解析器物理移除组合、547 个发布文件检查。此前 60 项核心/Host 定向回归与 18 项 SDK/安全/既有解析回归也通过。真实 SDK 探针使用实际 SessionStore、SessionProjectionRegistry 和持久事件折叠，不再用 projection 假替身。

最终差异检查确认解析器、协议、装配、统一解析模型、来源/共享工具、解析测试及 fixture 均未修改。真实 Cordis、SkillRegistry、MCP Config schema 参与测试；仅进程执行与远端连接端点受控，不宣称实际第三方 MCP/Hook 网络运行已验证。不推送、不发布、不修改用户 profile。

本轮没有把安装/来源更新的下载阶段移到仓库锁外；它们的写事务与补偿边界保守保留。已移出长锁的是只读更新检查。准备会话在当前 Manager 内存中持有，Web 负责过期/关闭释放；直接 Service API 调用方也必须按文档完成或释放会话。
