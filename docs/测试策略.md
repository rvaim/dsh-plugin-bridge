# 测试策略

> 当前源码一级目录为 10 个，目录及迁移映射见[解析器解耦重构说明](<解析器解耦重构说明.md>)。`0.6.0` 迁移当前 DSH SDK、运行接口和侧边栏入口；解析源码不变，模型版本保持 `5.0.0`、各协议实现版本保持 `1.1.0`。测试在项目内运行，不自动修改用户 profile。

## 1. 一键验证

```bash
npm run verify
```

该命令依次执行：

1. 清理旧编译产物；
2. TypeScript strict 编译；
3. Node.js 自动化测试；
4. 当前版本 SDK 的真实 Host/Client 注册、RPC 往返和释放；
5. 八种解析器组合的物理移除编译、公共入口加载和行为检查；
6. 发布文件、DSH bundle 和 `npm pack --dry-run` 检查。

当前完整结果以[解析器解耦验证报告](解析器解耦验证报告.md)为准；独立格式接入阶段结果保留在 [Agent Plugins 1.0.0 验证报告](<Agent Plugins 1.0.0 验证报告.md>)；传统格式修订记录保留在[插件协议兼容验证报告](插件协议兼容验证报告.md)，旧发布记录保留在[历史版本验证报告](历史版本验证报告.md)。

## 2. Source parser 测试

覆盖：

- Claude Marketplace；
- Codex Marketplace；
- 同一 Source 同时存在两种 Marketplace；
- 同名同真实目录合并；
- 同名不同目录冲突；
- 同目录关键元数据冲突；
- 损坏 JSON 与缺少必需字段；
- 不存在路径、路径逃逸、符号链接和普通文件目标；
- 外部 Git、git-subdir 与不支持位置；
- 单插件 Source；
- ZIP 单层包装目录；
- `paths`；
- Marketplace 之外的目录不会被递归猜测。

## 3. 本轮协议回归

新增 Manifest、Hook、Skill/MCP 和宿主执行契约测试分别覆盖平台合并、空值与覆盖顺序、合法事件与运行不支持分类、函数 modules、matcher、Handler 关键字段、sidecar 调用策略、Header 认证、延迟 fallback、当前 Shell execute/result、直接 argv、初始化等待、停止与失败健康状态。固定基线是 Codex 0.163.0 传统格式及 CC 2.1.304 / 2026-10-20 官方文档，具体证据见[方案](传统插件解析兼容方案.md)。这些都是受控回归，不等于任意第三方插件端到端运行通过。

## 4. Plugin parser 测试

真实 Claude Code/Codex 结构进入 parser，再检查 `CompatPlugin`：

```text
旧插件目录

   ↓
CompatPlugin
```

覆盖：

- Skill、MCP、Hook、Command、Agent；
- Claude/Codex 路径和环境变量；
- Codex 传统顶层组件字段、显式配置替换默认发现、空值/无效值回退、非法 `paths` 包装字段与 Marketplace manifest 回退；

- 非法能力路径和字段类型；

## 4. Adapter 与 runtime 测试

[runtime/adapters](<../src/runtime/adapters/>) 的测试直接构造统一结构，不依赖 Claude/Codex 原始 fixture，以证明两层真正解耦。Hook、MCP 和 Skill 实现分别位于 [hooks.ts](<../src/runtime/adapters/hooks.ts>)、[mcp.ts](<../src/runtime/adapters/mcp.ts>) 和 [skills.ts](<../src/runtime/adapters/skills.ts>)；搬迁后的测试沿用相同执行语义。

覆盖：

- adapter 不读取 `.claude-plugin`、`.codex-plugin`、`.mcp.json` 或 Hook 原始配置；
- Skill Provider 注册和撤销；
- MCP 子插件与工具生命周期；
- Hook 事件、payload、deny/context、取消和清理；
- 部分能力失败进入 `degraded`；
- 全部能力失败立即 dispose 父实例；
- parserVersion/sourceRevision 变化重新扫描；
- 重扫后保留 Source 候选诊断；
- 下游异常脱敏。

测试使用真实 Cordis Context/Fiber、Session projection、SkillRegistry 和官方 MCP Config schema；受控替身只提供进程执行与连接端点，避免执行用户命令或真实远端连接。新增 SDK 契约用例验证公开入口/Service 可直接挂载、未 inject 服务的读取边界、取消、失败清理与父实例撤销。它不是对真实远端 MCP 网络服务的声明。

## 5. Manager 与事务测试

覆盖：

- 显式/隐式 Source；
- 多 Plugin 选择与全有或全无安装；
- Source 只保存一份完整内容；
- Source 引用归零策略；
- 共享 Source 整体更新；
- `checkUpdates()` 探测目录/归档/Git Source 的 revision 变化；
- 新候选不自动安装；
- 已安装 Plugin 消失时拒绝更新；
- 第二个新版 Plugin 启动失败时整体恢复；
- 外部 Git Source 更新与回滚；
- 运行实例无法停止时保留正式内容和恢复材料；
- 管理别名与重复安装；
- 损坏 install 记录时保守阻止删除；
- 启用失败回写 disabled；
- dispose 失败时不先删文件；
- 并发重复安装与锁回收；
- 准备来源升为 explicit、被其他入口安装引用、跨网关会话及来源目录替换后的安全释放；
- 完成/取消/TTL 竞争、重复完成/取消、失败重试和关闭等待；
- 更新探测被 Promise 阻塞时 list/disable 可继续，revision 或引用变化后旧检查结果失效；
- repository 刷新不启动运行实例，manager 保留过期能力撤销并区分运行同步错误。

## 7. Web 主面板与 Remote 测试

覆盖：

- 单插件 Source 第一次拉取后直接安装；
- 多插件 Source 返回可访问候选并复用第一次固定的 Source 快照；
- 删除原始输入目录后仍可完成第二阶段安装，证明没有重复拉取；
- 取消选择回收无引用的隐式 Source；
- 同一 Source 并发选择时正确转交清理责任；
- Web list、启用、停用和卸载映射到 manager 生命周期；
- Web 更新检测会标记共享 Source 的全部插件，`update` RPC 复用原子更新事务；
- Web list 与安装结果只传输 error/warning 的公开诊断字段，并保留说明、代码、能力和文件；
- Typert Host/Remote 生成产物包含全部严格 RPC descriptor；
- Client bundle 使用 DSH `window.__ModuleLoader__` closure-factory，并进入 `dsh.client` 启动图；
- 实际浏览器 bundle 只注册同 ID 的 `sidebar.panellist` 与 `main`，不再注册设置入口，label 跟随当前语言；
- 当前 SDK Host/Client 注册器接受所有生成 codec，RPC 往返和非法参数拒绝有效，卸载后入口、字典与 namespace 被清理；
- 发布前在独立 DSH profile 中人工检查侧边栏切换、空状态、添加弹窗、多选、动态开关、卸载确认及暗/浅主题；项目内测试不代替真实浏览器验收。

本轮额外用真实 React、Chrome 和 SDK primitives/官方主题进行两轮离线演示验收，覆盖检索/筛选、两种读取失败保留数据、共享更新确认、输入法 Enter、选择阶段焦点、Tab 限制、低高度弹窗、卸载焦点和迟到选择请求回收。源码中的 `panel-model` 用例覆盖过滤语义；`usePluginBridge` 管理异步状态，行与弹窗组件只负责各自流程。

可审阅[架构与界面审查快照](架构与界面优化审查.md)、[本轮核心优化实施](核心架构优化实施.md)与[浏览器结果](../artifacts/plugin-bridge-ui/browser-results.json)。离线演示不修改用户 profile，也不代表当前 GUI 已安装此版。核心优化的来源所有权、锁隔离与 SDK 验收以本轮实施文档和定向测试为准。

## 9. 真实 DSH 契约探针

在安装了目标 peerDependencies 的 DSH profile 或源码 checkout 中运行：

```bash
npm run verify:dsh
```

探针核对：

- 根依赖中的 DSH SDK、Hook Protocol、生成器均与 `engines.dsh` 相同；
- 当前安装器接受本包清单，旧 DSH 版本被拒绝；
- Typert Host/Remote 八个方法全部使用严格 codec 工厂，可被真实注册器注册；
- 原故障中的旧 `schema` codec 被当前注册器拒绝；
- 当前 SDK 的 Client Remote 通过内存载体实际调用 Host Gateway，覆盖读取、卸载、非法参数和业务错误；
- 撤回 namespace 后不再向 Host 发起调用。

探针不打开 HTTP 服务、不安装到用户 profile，也不代表浏览器绘制或真实第三方插件执行已验证。

## 10. 新增兼容逻辑的要求

每次增加生态格式或能力适配时，应同时满足：

1. parser fixture/结构测试；
2. 统一结构断言；
3. adapter 独立测试；
4. 生命周期和 dispose 测试；
5. 失败恢复测试；
6. Secret 与路径安全测试；
7. 文档和兼容矩阵更新。
